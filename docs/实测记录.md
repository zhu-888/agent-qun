### 上线后群主发现的一个毛病：选完模型，选不了推理强度

**原因**：界面为了不把正开着的下拉菜单刷掉，用的判断是“焦点是不是还在下拉框上”。可选完一项之后，焦点常常还留在下拉框上，于是成员详情那一块从此不再刷新，“推理”下拉框就出不来。任务卡里选档位的下拉框用的是同一个判断，有同样的隐患。

**怎么复现的**：用真实的鼠标点了一下下拉框（焦点留在上面），再从后台把这位成员改回“自动”，详情里显示的还是旧的模型和推理强度，一直不变。

**怎么改的**：改成自己记“菜单什么时候点开的”——选了一项、焦点离开，或者过了 15 秒，都算关了。另外，选完模型后不等工作台回话，马上在界面上改过来。成员详情也不再因为窗口大小变化而关掉。

**改完实测**：先用真实的鼠标点模型下拉框，再选 GPT-6.1-Sol：推理下拉框当场出现（默认 low），工作台那边存成了 gpt-6.1-sol · low；把推理改成 xhigh，工作台那边跟着变；改回“自动选模型”，推理下拉框消失，工作台那边回到自动。测完 Codex 留在“自动”。

**没能验证的**：内置浏览器里看不到系统弹出的那个菜单本身，“选一项”这一步是用脚本代替的；在群主自己的 Chrome 里用真鼠标完整点一遍，还得他自己试。

### 群主说“还是选不了”：真正的原因是连接被占满

上面那个焦点的毛病是真的，但不是群主那边选不了的原因。他发来的截图里，模型下拉框显示的是他刚选的 Fable 5.2，旁边却还是“上次 Opus 5.5”；我去看工作台存的设置，那个项目里根本没有记下这次选择——这个请求没有到达工作台。

**原因**：浏览器对同一个地址最多同时开 6 条连接。以前每个工作台标签页要开两条不断线的推送连接（一条收应用级的事，一条收当前项目的事）。查了一下当时的连接：Chrome 正好占着 6 条，也就是同时开着三个工作台标签页，名额满了。之后页面上任何操作（选模型、改名、发消息）都排在后面发不出去，标签页上的转圈也一直在转。

**怎么改的**

- 一个标签页只开一条推送连接，两类事都走它。
- 标签页切到后台 10 秒后断开连接，把名额让出来；回到前台再连上，并把状态重新读一遍。
- 老页面用的那两条连接，工作台现在直接回“不用再连了”，所以不用等群主逐个刷新，旧标签页占着的名额在工作台重启后就放掉了。
- 推送连接改到页面载入完成之后再开，标签页上的转圈不会再一直转。

**实测**

| 看了什么 | 结果 |
|---|---|
| 改之前，各程序连着工作台的连接数 | Chrome 6 条（占满） |
| 工作台重启后几秒 | 0 条：旧页面都放手了 |
| 内置浏览器重新打开页面 | 只开了一条 `/api/events?p=…`；页面状态是“载入完成” |
| 选 Claude 的模型为 Fable 5.2 | 推理下拉框当场出现（low 到 max，默认 high），工作台存成 fable · high；改成 max，存成 max；改回自动，存成自动 |
| 模拟切到后台 | 12 秒后连接数归零 |
| 模拟回到前台 | 重新连上（1 条推送连接），页面内容重新读了一遍 |

**没能验证的**：“切到后台 / 回到前台”是用脚本模拟的；群主自己的 Chrome 里刷新之后是不是好了，要他自己试。同时让 6 个工作台标签页都显示在屏幕上（6 个窗口并排）的话，名额还是会满，这种情况没有处理。

## 二十一、第 3 项：没做完自动重试，连着 3 次熔断（2026-11-18）

以前一次运行出错或超时，就直接标失败、提醒群主点“重试”，没有自动重试，也没有“连着失败几次”的概念。被沙箱拦下的操作，工作台也不知道，只能靠成员自己在回复里说。现在：

- 出错、超时、中间有操作被系统沙箱拦下，都算“没完成”一次。按同一条线算（同一位成员在同一张任务卡或同一个对话上），顺利跑完就清零；被重启打断、群主停止、被叫停、额度用尽的不算，也不打断计数。
- 前两次自动再试：第 1 次等 1 分钟，第 2 次等 5 分钟，群里留一句说明，不打扰群主。再试时提示里写上次为什么没完成、当时在跑什么命令。等的期间群主新发的消息马上送过去，成员之间的 @ 照样等。
- 连着第 3 次熔断：唤醒标失败，任务卡标“卡住”（工作台），提醒群主（带“重试”“查看过程”），不叫协调员。群主点“重试”照样能跑，再失败还是直接交给群主。
- 成员程序报回来的工具结果里认“被拦”的报错（三位成员各自的格式），运行结束时在群里说被拦了什么：在跑的命令或文件、报错关键词。只认报错的固定格式，正文里提到这几个词不算。

**规则测试**：47 项全过（新增 5 项：出错/超时重试两次后熔断、群主重试、跑通清零；等待期间群主消息不用等、成员 @ 照样等；拦截报错的识别（含乱码清理）和群里说明、连着 3 次被拦停下；计数规则；JSON 报错只显示那句话）。

**真实成员实测**（三个测试项目，测完已移除并移进废纸篓）：

| 实测 | 做法 | 结果 |
|---|---|---|
| 出错熔断 | 给 Codex 指定一个不存在的模型，派一张卡 | 21:54:25 第 1 次出错 → 1 分钟后 21:55:30 第 2 次 → 5 分钟后 22:00:37 第 3 次，熔断：T1 标“卡住（工作台）”，提醒群主。点“重试”照样跑了一次，失败后直接交给群主（“连续 4 次”），没有再自动重试。四次都是接口直接拒绝，0 token |
| 超时重试 | 超时设成 1 分钟，让 Codex `sleep 90` | 1 分钟被停，1 分钟后自动再试。再试时它读到“上次超过 1 分钟被自动停止，当时在执行 sleep 90”，没有再跑一遍 sleep，而是想查进程确认（`ps` 被它自带的沙箱拦下，群里如实说了），最后如实回复“无法确认是否跑完，未重复执行”。这次运行算“被拦”一次，所以计数没有清零 |
| 被沙箱拦下 | 让三位成员各往不归自己的目录写一次 | Claude：Write 工具和 shell 两处都认出来了。DeepSeek：认出来了，但发现了下面那个问题，修好后重测，`date` 正常、越界写入被拦并认出。Codex：见下面 |

- **token**：熔断本身不调用模型。自动重试那次就是成员再跑一次：Codex 超时后的那次重试输入 12.1 万（其中缓存 11.3 万），输出 253。拦截测试里每次运行和平常一样（Claude Sonnet 约 6.2 万输入、大部分缓存；Codex 约 5 万）。DeepSeek 两次共约三毛钱（第一次没命中缓存，花了两毛多；第二次不到两分钱）。

**测试中发现并修掉的**：

- **DeepSeek 跑不了任何 shell 命令**。DeepSeek Harness 11 月 13 日升级到新版本后，会给每条命令再套一层它自己的沙箱（workspace-write），而工作台已经用 `sandbox-exec` 把它整个包起来了，沙箱不能套沙箱，命令一律报“no sandbox backend is usable … refusing to run the command unconfined”，根本没执行。以前的版本在同样的设置下能正常跑 `sleep 15`。现在工作台启动它时用补丁把它的默认权限设成不再自己套沙箱，写入边界照样由外层沙箱强制。只对新开的 DeepSeek 会话生效。修好后：`date` 正常输出，往别人的目录写照样被拒绝。
- **报错原文是一整段 JSON**（接口返回的 400）：群里现在只显示里面那句话。
- **被拦提示里中文路径成了乱码**：zsh 报错时把中文转义了。现在提示里写的是成员当时在跑的命令（比如「echo hi > 共享区/越界6.txt」），报错里的乱码换成省略号。
- **“重试”按钮会把项目里所有失败的唤醒一起重试**：现在只重试这一次运行的。
- 一开始的提示语写“多半是写到了不归它的位置”，但 `ps` 这种被拦的不是写文件，改成“写到了不归它的位置，或者做了沙箱不允许的事”。

**测试中看到的 Codex 行为**：让 Codex 往别人的目录写，它两次都没有真的运行命令（过程记录里没有任何命令执行），而是照着群规“预判”会被拒绝，第二次还编了一段“原样输出”。工作台没有把这两次记成被拦，因为它只认真实的命令输出。成员说的话和实际跑的命令可能对不上，这一点要靠“查看过程”核对。

**没有验证的**：真实网络中断时的自动重试（规则测试里模拟过；上一项实测碰到的 22 分钟 DNS 故障这次没再出现）；Codex 用改文件工具（不是 shell）写越界被拒绝时的格式，是按它的接口文档写的识别，没有真的触发过；旧的 DeepSeek 会话（这次修复之前开的）仍然跑不了命令，要等它换新会话。

## 二十二、第 4 项：成员干活期间卡被推进了，标“已过时”（2026-11-19）

以前成员在一张卡上干活时，如果这张卡被取消、被别人提交或审查，它交回来的话照样发到群里，里面的 @ 照样叫醒别人。可它写的时候并不知道卡已经变了。现在：

- 成员开跑时记下这张卡的记录到了哪一条。它交回的话（最后的回复、中途的回复、`qun say`）发出前，查一下这之后有没有“别人”推进了这张卡：提交、审查通过或没通过、验收、打回、重新打开、改派、取消、撤回提交。
- 有的话，这条照样发到群里，但标“已过时”，写明有了什么新进展；里面 @ 的成员先不叫醒，由群主点“照样送出”决定。给别的成员看的群聊里，这条前面标“（已过时）”。

- 不调用模型，不让成员多跑一次。

**规则测试**：49 项全过（新增 2 项：卡被取消后回复标过时、@ 不叫醒、照样送出只送一次；自己这次运行的提交不算、别人重新提交后审查人的 `qun say` 和回复都标过时、之后给成员看的群聊里带“（已过时）”）。

## 二十三、第 5 项：git 项目每张卡一个工作区，验收时合并（2026-11-19）

以前写入范围只能是 `共享区/` 下面的目录，项目是代码仓库时成员改不了代码本身，两张卡也不能各改一份同一个文件。现在项目文件夹本身是 git 仓库时：

- 负责人第一次在卡上干活时，工作台在 `.workgroup/worktrees/<卡号>/` 建一个工作区（分支 `workgroup/<卡号>`），负责人的命令从那里启动。子任务从父任务的分支分出来。
- 写入范围照旧强制：只有负责人做这张卡的会话能写它的工作区，提交后锁定；审查人、别的卡写不进去。项目里的原件、`.git` 对成员只读。
- 成员不自己 `git commit`。`qun task submit` 时工作台替它提交到分支，提交号记在卡上。
- 子任务审查通过合进父任务的工作区；顶层卡群主点“验收并合并”时合进项目当前分支。合并前先用 `git merge-tree` 算一遍，有冲突、会覆盖项目里没提交的改动、或者项目不在原来的分支上，都不合并并说明原因。有冲突的卡打回时，工作台把最新改动合进它的工作区、留下冲突标记让负责人改。
- 从不推送。卡结束后清理工作区；已合并或没改动的分支删掉，没合并的留着。
- 改动快照也拍工作区里的改动。Claude 从工作区启动时带 `--settings {"claudeMdExcludes": [项目根的 CLAUDE.md]}`，免得同一份 CLAUDE.md 读两遍。

**规则测试**：56 项全过（新增 7 项：完整流程和清理；冲突不合并、打回后留冲突标记、标记没改完不能提交、改完能合；项目里没提交的改动会被覆盖时不合并、不在原分支时不合并；子任务合进父任务、子任务之间冲突时留在分支上并告诉父任务负责人；非 git 项目和嵌在别的仓库里的项目不建、取消的卡把没提交的改动存到分支上；快照拍工作区、能撤回、合并清理后撤不了；用系统沙箱实测负责人能写自己的工作区、改不了原件和 `.git`、别的卡和审查人写不进来）。

**真实成员实测**（项目“工作区实测”，一个有 `price.js` 和 `test.js` 的小 git 仓库，测完已移除并移进废纸篓）：

| 实测 | 做法 | 结果 |
|---|---|---|
| 1 | 不要审查，派给 Codex：在 `price.js` 加 `discount(sum, rate)` 并补测试 | Codex 从 T1 的工作区启动，改了 2 个文件，在工作区里跑 `node test.js` 通过，提交；工作台把改动提交到 `workgroup/T1`（提交人“Codex（多 Agent 工作台）”），main 没动，没有一次被沙箱拦下。点验收后合并进 main，项目里 `node test.js` 通过；工作区和分支自动清理，卡上的成果路径改成了项目里的 `price.js`、`test.js` |

- **token**：这一项本身不调用模型。每张卡的新会话提示多了约 390 个字的工作区说明（实测提示总长 3826 字，其中工作区相关 393 字）。实测花费：Codex（gpt-6.1-sol · xhigh）输入 14.0 万（缓存 11.9 万）、输出 2.2k；Claude 第一轮（Opus 5.5 · xhigh）输入 16.8 万（缓存 14.7 万）、输出 1.5k；Claude 解冲突那一轮因为是被打回的返工，按规则升了一档（Fable 5.2 · xhigh），输入 19.3 万（缓存 16.6 万）、输出 2.4k。冲突那一轮是解冲突本来就要花的。

**没有验证的**：DeepSeek 在工作区里干活（和 Claude 走同一条路，省钱没测）；子任务之间真实发生冲突、父任务负责人手工合（规则测试里测过）；`CLAUDE.md` 跳过的效果（测试仓库里没有 `CLAUDE.md`，只确认了 Claude 带着这个设置能正常运行）；手机上点“验收并合并”（和电脑走同一个接口）；很大的仓库建工作区要多久。

## 二十四、原第 6 项：逐字显示；不做常驻进程和审批卡片；放开上网查资料；成员不能推送（2026-11-20）

原第 6 项“Claude 常驻、逐字显示、审批卡片”拆开讨论后定下：

- **常驻进程不做**。实测新起一个 Claude 进程 2.2 到 3.3 秒出第一个字，同一个进程接着聊 1.1 秒；每次只差一两秒，也不省 token（缓存能留 1 小时，原来的做法输入里就有 85% 以上走缓存）。一个空闲的 Claude 进程约占 230 MB；写入范围是进程启动时定死的，成员的角色、工作区、模型档位一变就得重启，常驻的好处基本没了。
- **审批卡片不做**，继续“不弹窗、靠沙箱”。但补上一个漏洞：成员用了要人批准的工具，以前被拒后群里一个字都没有。现在也算“被拦下”，群里会说明。
- **放开只读的上网查资料**：Claude 加上搜索（WebSearch）和打开网页（WebFetch）两个工具；Codex 的沙箱打开联网（整理群摘要的一次性小活不开）；DeepSeek 本来就能联网。能写哪里不变。
- **逐字显示**：输入框上方“正在做”那一行跟着成员走，显示正在运行的命令、“正在想”（Claude 还写想了约多少 token）、或者正在说的最新几个字；点这一行打开这次运行的全部过程，最下面“正在写…”是还没写完的那段话，面板跟着刷新。聊天区只放最终回复。Claude 加了 `--include-partial-messages`，Codex 接上了 `item/agentMessage/delta`，DeepSeek 的无界面模式只整段给（查了它的安装包，只有整段写完时才输出 text），就按整段刷新。推给界面最多每 0.15 秒一次。
- **成员不能推送**（讨论时我说了“永远不会推送到 GitHub”，可放开联网后 Codex 也能推了，Claude、DeepSeek 以前就能，所以补上）：成员的 git 用一份工作台的全局配置（`GIT_CONFIG_GLOBAL`），照常引用群主自己的配置，推送地址一律改写到 `qunnopush://`，由工作台的小程序拒绝，报 `git push: operation not permitted: …`。不用同名的 git 包装命令，是因为 Codex 的命令从登录式 shell 启动，会把工作台加的命令目录挪到 Homebrew 后面。

**规则测试**：60 项全过（新增 4 项：用一个假的 claude 命令吐事件，测逐字只吐说的话、思考只显示“正在想”和想了多少、碎片不进运行记录、一次性小活不逐字；工作台把同一段话拼起来、那一行只放最后 240 个字、推送限频、写完和跑完清掉；工具没放开的识别只认报错的工具结果、群里怎么说、Claude 的工具清单、Codex 的联网参数；推送被拒、远端什么也没收到、工作台认得出、群主自己推送和成员拉取照常）。
